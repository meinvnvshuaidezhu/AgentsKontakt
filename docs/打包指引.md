# AgentsKontakt · 64 位安装包打包指引（任务书）

> **定位**：本文是交给执行 agent 的**打包任务书**——按步骤做完即产出一个可分发的 64 位 Windows 安装包。每步带判据；执行中发现的与本指引不符的事实，如实记录进交付报告，不要静默绕过。
> **验收基准**：本文 S7 清单（干净环境 silent 安装全量核对；打包完成 ≠ 完成，验收全过才算）。
> **采集时点**：2026-10-31。基于当日仓库现状（app\Installer.cs 459 行、scripts\ops\install.ps1 已具备完整安装流程）。

## 一、任务定义

**产出物**：一个 zip 分发包 `dist\AgentsKontakt-x64-<版本号>.zip`，解压到任意目录后，满足两条安装路径之一即可用：

```
路径A（图形）：双击 app\AgentsKontaktPost.exe --install（或先启动 exe 用面板）
路径B（脚本）：powershell -NoProfile -ExecutionPolicy Bypass -File scripts\ops\install.ps1
```

安装后的布局（install.ps1 已实现，勿改动语义）：

| 目录 | 内容 | 性质 |
|---|---|---|
| `%LOCALAPPDATA%\Programs\AgentsKontakt` | 代码：app\（exe＋WebView2 dll＋ico）、scripts\、templates\、assets\、config\ | 只读也行 |
| `%LOCALAPPDATA%\AgentsKontakt` | 数据根：mailboxes\ registry\ archive\ logs\ post\ ＋**自包含的 scripts\ templates\ config\ assets\** ＋**文档层** | 必须可写 |

## 二、现状盘点（先读，避免重复造轮子）

**已有，直接用**：

| 组件 | 位置 | 说明 |
|---|---|---|
| 64 位构建 | `scripts\ops\build-exe.ps1` | 用系统自带 `Framework64\v4.0.30319\csc.exe`，`/platform:x64`，零外部 SDK；源码须 UTF-8 带 BOM（脚本自动处理） |
| 安装器 | `scripts\ops\install.ps1` | 拷代码→建数据树→staged 卡片→快捷方式→双层自启（计划任务＋HKCU Run）→Defender 排除（可跳过）→init.ps1 |
| exe 自注册 | `app\Installer.cs` | `--install/--uninstall/--register-autostart`，内部委托 install.ps1（单一实现不漂移） |
| 卸载 | `scripts\ops\uninstall.ps1` | 数据默认保留（信件/归档是用户资产） |
| 数据根解析 | `Program.ResolveDataDir` | `--data` ＞ `MAILBOX_ROOT` ＞ 便携布局 ＞ `%LOCALAPPDATA%\AgentsKontakt` |

**缺口，本次要补**（全部落在下文步骤里）：

1. 🔴 **文档层不入包**：install.ps1 的拷贝清单只有 app/scripts/templates/assets/config——AGENTS.md、PROTOCOL.md、docs\、skills\ 都不会进数据根，**agent 被指向安装目录时找不到任何入口文档**。
2. 🔴 **无 staging/打包流程**：没有 dist\ 发布树规范、没有 zip 产物、没有包内容清单。
3. 🔴 **registry 含本机专属卡片**：源仓库 registry\ 里本机专属卡片的 wake 链指向本机绝对路径与专属包装器，**随包分发到别的机器是有害的**（邮局会去敲不存在的命令）。
4. 🟡 **升级覆盖 config**：install.ps1 对 templates/config/assets 用 `Copy-Item -Force` 进数据根——重装/升级会冲掉用户调过优的 `config\system.json`。
5. 🟡 exe 内置 fallback（`Installer.cs` 的 `WriteDataConfig`）不同步拷文档——PowerShell 不可用时文档仍缺席，列为可选加固。

## 四、执行步骤

### S1 构建版本号对齐

版本号唯一权威 = `app\AssemblyInfo.cs` 的 `AssemblyVersion/FileVersion`。发版前按语义化递增（改动仅脚本/文档 → 修订号；新增功能 → 次版本号），并确认三处一致：AssemblyInfo.cs ＝ zip 文件名 ＝ 交付报告。

### S2 构建 64 位 exe

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\ops\build-exe.ps1
```

判据：`csc exit: 0`；输出 exe 的 `VersionInfo.FileVersion` = S1 版本号；exe 为 x64（`(Get-Item app\AgentsKontaktPost.exe) | Select Processor` 或 dumpbin 核对，`/platform:x64` 已由脚本保证）。

### S3 代码改动（本任务书要求的唯一脚本修改）

**S3a · install.ps1 增加文档层拷贝**（补缺口 1）。在"scripts staged into data dir"步骤之后新增一段：把 `AGENTS.md`、`PROTOCOL.md`、`README.md` 三个根级文档＋`docs\`、`skills\` 两个目录拷进 `$DataDir`（`docs\`、`skills\` 用 `-Recurse -Force`；根级文档同样 `-Force`，它们是协议文本，升级理应刷新）。**注意保持文件 UTF-8 BOM**（含中文文件名的快捷方式步骤已有此纪律，新代码同样遵守）。`安装指南.md` 物理位于 `docs\` 下随目录进入数据根，zip 根由 `安装说明.txt` 指向根目录的 AGENTS.md（实际生成文案以 build-package.ps1 为准），不做双份拷贝（防漂移）。**拷贝完成后写 SKILL 指针文件**（2026-11-09 新增，配合 `skills\mailbox\skill-sync.ps1` 的动态数据根解析）：向**部署到 agent 侧的技能目录**（如 ZCode 系的 `%USERPROFILE%\.agents\skills\mailbox\`）写入 `.mailbox-root`（单行 = `$DataDir` 绝对路径，UTF-8 无 BOM 纯 ASCII 路径即可）；该文件是机器配置**绝不打进 zip**——安装位置与用户名因机器而异，靠安装时写入而非打包时携带。若安装器无法得知 agent 侧技能目录，则跳过——agent 接入时按 AGENTS.md「首次接入」/ PROTOCOL 接入流程第 4 步 / 安装指南第 4 步自助部署（复制整目录＋写指针＋skill-sync 自检），三副本链说明见 Agent操作指引 §6。

**S3b · config 防覆盖**（补缺口 4）。把 config 的拷贝改为「不存在才拷」：`config\system.json` 已存在时跳过（用户调优优先），仅新键新文件落盘。templates/assets 维持 `-Force`（它们是模板不是用户数据）。

**S3c ·（可选加固）** `app\Installer.cs` 的 `WriteDataConfig` fallback 同步补文档拷贝。不做不阻塞，做了在报告里注明。

🔴 S3 每处改动后重跑 S0-2 回归，全绿才算改完。

### S4 建 staging 发布树

在 `dist\stage-AgentsKontakt-x64-<版本号>\` 下组装（**从 git 干净检出或按下列清单从工作树挑选，二选一，报告里注明用了哪种**）：

```
stage-AgentsKontakt-x64-<版本号>\
├─ app\
│   ├─ AgentsKontaktPost.exe          # S2 产物
│   ├─ Microsoft.Web.WebView2.Core.dll / WinForms.dll / WebView2Loader.dll / post.ico
│   └─ (Program.cs / Installer.cs / AssemblyInfo.cs / Launcher.cs —— 保留，自包含可审计)
│   # 排除：debug.log、userdata\
├─ scripts\                            # 以 build-package.ps1 的 excludes 为准：ops 构建脚本、
│                                      # tests（除 test-stub/test-request）、adapters 不入包
├─ templates\  assets\  config\
├─ skills\                             # 含 mailbox\SKILL.md（AGENTS.md 引用了它）
├─ docs\                               # agent 面向文档：安装指南 / Agent操作指引
│                                      # 🔴 排除：打包指引.md、并发唤醒需求.md、协议修订案-v3-*.md（dev/历史文档）
├─ registry\
│   └─ testbot.md                      # 🔴 唯一随包卡片：wake 用相对路径 scripts\test-stub.ps1，跨机可移植；
│                                      #    除 testbot 外的卡片一律不进包（机器专属）
├─ AGENTS.md  PROTOCOL.md  README.md   # 入口文档（安装指南在 docs\ 下，不双份拷贝）
└─ 安装说明.txt                        # 新写，人读快速开始（见 S5）
```

🔴 **排除清单（一条都不许进包）**：`mailboxes\`（内容）、`archive\`、`logs\`、`post\`、`dashboard\`（生成物）、`.git\`、`.zcode\`、`.workbuddy\`、`vendor\`、`archive.bak-*\`、`NUL`、`debug.log`、`*.bak-*`、任何 `__pycache__`、`app\userdata\`。判据：包内 grep 不到本机任何真实信件、归档、日志、git 历史。

🔴 **运行时数据必须 git-tracked（2026-11-05 起）**：staging 只取 git 追踪文件——`config\i18n.<lang>.psd1`（文案映射表，install.ps1 对 config 缺失才拷，升级自动补新文件）等新增运行时数据若未 `git add` 会**静默不进包**（fresh install 回落英文输出）。build-package.ps1 已加 i18n 闸：stage 缺 `config\i18n.zh-CN.psd1` 直接 fail。

### S5 写 `安装说明.txt`（zip 根，人读，10 行以内）

内容要点：这是什么（一句话）→ 两条安装命令（路径A/B 原文）→ 装完后数据根在哪、怎么把 agent 接进来（指向 安装指南.md 一句话）→ 卸载命令。UTF-8 BOM。

### S6 装配 zip ＋ Setup.exe（v2.2.1 起：一条命令）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\ops\build-package.ps1
```

脚本完成：git 追踪清单 staging（含排除规则）→ 新 exe 覆盖 → 安装说明.txt → 卫生扫描 → 载荷 zip → 编译 Setup.exe（载荷内嵌为资源 `payload.zip`；Setup.cs 先强制 UTF-8 BOM——中文 UI 字符串，BOM-less 会被 csc 按 GBK 读成 mojibake）。产出 `dist\AgentsKontakt-x64-<版本号>.zip` ＋ `dist\AgentsKontakt-x64-<版本号>-Setup.exe`。

判据：zip 可完整解压、抽查哈希一致；Setup.exe 存在且版本号正确；卫生扫描零命中。Setup.exe 的交互流程（确认对话框/启动询问）由 owner 人工双击验证，静默模式（`--silent --install-dir --data-dir --no-autostart --no-defender`）由执行 agent 隔离验收。

### S7 干净环境验收

在隔离沙箱（`%TEMP%` 下新建目录 + `--silent --install-dir <沙箱> --no-defender --no-shortcuts --no-autostart`）或干净 x64 备用机全量执行；**别在本开发机上装**——会污染真实数据根。逐条核对，全过才算打包完成：

1. 安装后 `app\AgentsKontaktPost.exe` 的 `FileVersion` = 本版版本号；
2. 数据根五区 + `registry\` / `archive\` / `logs\` 目录树齐全；
3. `AGENTS.md`、`PROTOCOL.md`、`README.md` 在数据根根层；
4. `docs\` 含 `安装指南.md`、`Agent操作指引.md`，且**不含** `打包指引.md`（dev 文档）；
5. `skills\mailbox\` 含 `SKILL.md` 与 `skill-sync.ps1`，自检输出 `FRESH`；
6. `config\i18n.zh-CN.psd1` 就位（缺它 = 全英文输出）；
7. `registry\` 仅 `testbot.md`（无本机专属卡片）；
8. `scripts\tests\test-request.py` 存在（新装机验收硬性关口，缺了验收直接 file-not-found）；
9. `scripts\registry-audit.ps1` 存在且可跑（`fail=0 warn=0`）；
10. 包内无真实信件/归档/日志/`post\`/`.git`/`userdata`（卫生扫描零命中）；
11. 卸载入口可用（快捷方式或 `--uninstall`）；
12. 升级语义不破：重装不覆盖 `config\system.json`、不删信件与归档。

Setup.exe 的交互流程（确认对话框/启动询问）由 owner 人工双击验证；静默模式由执行 agent 在沙箱验收。**验收全过才算打包完成。**

⚠️ **沙箱验收的两个已知副作用（每次验完必须还原）**：install.ps1 会写「机器级单点」，沙箱安装同样会覆盖本机真值——① `HKCU\...\Uninstall\AgentsKontaktPost` 的 `InstallLocation` / `UninstallString` / `DisplayIcon` / `DisplayVersion` 被指到沙箱路径；② `<技能目录>\mailbox\.mailbox-root` 被改写成沙箱数据根。装完立刻把两者指回生产安装目录（否则设置→应用里的卸载项会指向已删除的沙箱、agent 的 SKILL 也会找错根）。

### S8 交付报告与归档

交付报告（md，放 `dist\<版本号>-release-report.md`）必须包含：版本号与三处一致性核对结果、S3 改动 diff 摘要、staging 清单与排除项核对、回归与验收结果（逐 AR 判据）、执行中发现与指引不符的事实、**升级遗留清查清单（见 S8a，必备小节）**。staging 树验收后可删，zip 与报告保留。

### S8a 升级遗留清查清单（报告必备小节；owner 指令 2026-11-11 固化）

**背景**：install.ps1 的语义是「只增改、不删除」——历史版本装过、本版不再分发的文件（源已删 / 排除规则新增 / 改名搬迁）会在生产数据根永久残留。2.4.3.2 升级时实际发现 4 个此类残留（协议修订案-v3、并发唤醒需求、收发流程图.html、打包指引.md），均已清理。**每次打包必须评估并交付这份清单，升级后按清单清查生产。**

产出方法（三查）：

1. **源删除**：`git diff --diff-filter=D --name-only <上一版打包时的 commit>..HEAD` —— 本版从仓库删除的文件；
2. **排除规则变化**：diff `scripts\ops\build-package.ps1` 的 staging 排除与 `scripts\ops\install.ps1` 的 `$devOnly` 正则（两处独立过滤，任一变化都意味着「以前分发、现在不分发」）；
3. **改名/搬迁**：`git diff --diff-filter=R --name-only <同上>` 加人工核对 docs\、skills\ 目录结构变化。

报告小节格式：逐文件列出「文件名 + 残留原因分类（源已删/排除规则新增/改名搬迁）+ 处置建议（生产可直接删 / 需 owner 确认）」。**纯文档与 dev 工具可直接定性；靠近用户资产的（config、registry、templates）一律标「需 owner 确认」**。

**生产升级后的清查动作**（升级完成时执行）：以 `git ls-files`（`-c core.quotepath=false`；排除 mailboxes/archive/logs/post/dashboard/userdata/data/.workbuddy 等运行时目录）为基准反扫生产数据根，对 EXTRA 文件逐个定性：运行时资产（留）/ 旧版残留（删）/ 手工资产（问 owner）。注意 PowerShell 5.1 会把 git 的 UTF-8 中文路径解成 GBK 乱码导致误报——用 Python 或带 BOM 的脚本跑。清查完在当版报告追加一行结果。

## 六、红线（违反任何一条 = 打包失败）

1. 🔴 真实信件、归档、日志、`.git`、本机 agent 卡片**绝不入包**（S4 排除清单）。
2. 🔴 改动任何 `.ps1` 后必须重跑沙箱回归，全绿才继续。
3. 🔴 含中文路径/文件名的脚本保持 **UTF-8 BOM**（PowerShell 5.1 无 BOM 按 GBK 读，快捷方式名会变乱码）。
4. 🔴 不修改安装语义（目录布局、数据根解析、卸载保留数据）——发现疑似 bug 记进报告，由维护者裁决，不自行改设计。
5. 🔴 版本号三处一致（AssemblyInfo / zip 名 / 报告），不复用旧版本号。

打包完成 = S0–S8 全过 ＋ S7 验收判据全过 ＋ 交付报告落盘。三者缺一，向派活方如实报告缺什么，不要含糊交付。
